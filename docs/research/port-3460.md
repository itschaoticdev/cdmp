# Port to CrimsonDesert.exe 1.0.0.3460 (offline, not yet run in game)

Build 1.0.0.3460, PE timestamp `0x6AE58024`, Pearl Abyss signature valid. It ships with the
2026-10-29 DLC. The 2976 exe was not available, so `tools/port/cd_port.py` (OLD → NEW) could not
run. Every value below comes from the new exe alone, using the 2976 research as the key.

**Nothing here has been confirmed with `cdmp_probe`.** Do not sign or publish a build from this
branch before someone who owns the game has run it.

## Message ids (all of them)

`tools/port/troc_catalog.py EXE rtti.json out.csv` (needs `tools/scripts/rtti_dump.py` output).
In the file, every static `Troc` instance carries the base `pa::Troc` vtable and its opcode at
`+0x0C`. Each message's dynamic initializer is `lea r,[rip+derived vtable]; mov [rip+instance],r`,
and the RTTI name of that vtable names the instance. 3460: 1,175 messages (2976: 1,115), all
named, none ambiguous → `troc_messages_3460.csv`.

Checks: `ConnectToServerAck` = 1002 with sizes 11/11 and `ActorLoadDataAck` = 2005, as in 2976.
The two server writers below were found by the new ids 3136 and 2907 as immediates. Most ids
moved (e.g. `MoveActorReq` 2556 → 2833), so a 2976 mod on 3460 sends the wrong messages.

## Not ported (needs the game)

- Struct offsets, payload layouts and sizes (`kRelayedAcks` sizes, `kLoad*FromEnd`, stat ids…).
  The AOBs above still contain `+0x30`, `+0x68`, `+0x90`, `+0xC8`, so the player chain looks
  unchanged, but a DLC can grow any message.
- `src/common/enemy_tables_2976.h` comes from the game's data archives, not the exe. New DLC
  enemies are missing from it.
- First run: `cdmp_probe` → read `[[[ctrl+0x140]+0x2C0]]` for kVtPhysicsObject, check the camera
  and minimap hooks, and capture a few packets to compare payload sizes with 2976.
