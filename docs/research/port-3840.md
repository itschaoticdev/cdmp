# Port to CrimsonDesert.exe 1.0.0.3840 (offline, not yet run in game)

Build 1.0.0.3840, Steam build 26949954 (2026-11-26), PE timestamp `0x6B07E5E9`.
The 3732 exe was never on the box, so this was ported from **3460** and cross-checked from **2976**.

## Message ids

`troc_catalog.py` → `troc_messages_3840.csv`: 1,193 messages (3732: 1,179), all named, none ambiguous.
`ActorLoadDataAck` = 2005 (unchanged).

🚩 **The 3732 port only updated the `kOp*` ids in `offsets.h`.** 74 ids in 11 other files
(enemy_relay, guest_hits, player_hits, loot_twin, native_suppress, local_capture, aggro_test,
attack_probe, piece4_test, remote_puppet, troc_sniffer) plus 3 raw literals were still **3460**
values on 3732. Loading-screen detection, enemy sync, hits, loot and the copy's catch release
all used wrong messages there. Now every one is mapped by name (`TrocTr` + the constant's name;
`kOpAttackTargetAck`/`kOpAttackerAck` = `PostProcessAttackResult_*`). Each old value was checked
against the 3460 or 3732 catalog before it was replaced. 92 of 96 changed.

## Message layouts (cdmp 0.4.1)

**Why the other player's copy stood still (0.3.x on 3460/3732, 0.4.0 on 3840):** the ports
moved the opcodes but kept the 2976 *payload layouts*. Every MoveActorReq on 3840 is 518
bytes, not 514, and every StartActionReq is 729, not 725. `capture_observe_c2s` dropped
anything of the wrong size without a word, so the sender never sent a single Move (Bunzeekio's
3732 2-player log: "events in 0-5" while the host walked 70 m; host stuck on "Time sync:
waiting for the game clock (move once)"). The copy spawned (ActorLoadData is variable-size and
unchanged) but nothing moved it.

Measured with `tools/port/troc_layout.py`: the game's own `pa::TrocTr*` parsers (vtable slot 2)
run in unicorn over a fake payload, every Read logged. On 2976 it gives the sizes captured
live (Move 514/235, StartAction 725, Rotate 176/177), which validates it.

Evidence that 0x44 / 0xD4 are the parent / ts: StartAction shows the identical change (u32 +
transform block → 3 vec3 + u64 right before Path.local, parent gone from the middle of Path,
ts one byte earlier), and the Ack's extra byte still sits right before the last u64 + u32
pair (old DE/E6, new E2/EA). The mod logs `Capture: Move #1 layout check: ts +0xD4 = ... |
game clock ...` so the first tester log confirms it: ts must be within ~1 s of the clock.

Not ported (needs one `[sniffer] record=1` capture on 3840): AAR instance/hash offsets,
UpdateWallUpData memory offsets.

Protocol version 10 (0.4.0 peers are refused with a version message, not half-working).
